## 4. 技术栈

| 层级 | 技术 | 版本/规格 | 选型理由 |
|------|------|----------|---------|
| **服务器** | 华为 TaiShan 200 | 鲲鹏 920 | 国产 ARM 处理器，满足信创要求 |
| **虚拟化** | FusionCompute 8.x | 集群 HA+DRS | 华为企业级虚拟化平台 |
| **操作系统** | openEuler 22.03 LTS SP2 | ARM64 | 华为开源操作系统，鲲鹏原生支持 |
| **容器引擎** | Docker CE | 24.x | 业界标准，ARM64 支持完善 |
| **容器编排** | Docker Compose | v2.20+ | 插件安装，适合单机多容器场景 |
| **博客系统** | Halo | v2.x | 国产开源（GitHub 30k+ Star），云原生友好，支持 Markdown |
| **数据库** | MySQL | 8.0.x | 成熟稳定，ARM64 官方镜像可用 |
| **反向代理** | Nginx | 1.24.x | 高性能，SSL 终端 + 静态资源缓存 |
| **SSL** | OpenSSL | 3.0 | 自签名证书（POC阶段）/ Let's Encrypt（生产） |
| **监控** | Prometheus | 2.47 | CNCF 标准，多维度指标采集 |
| **可视化** | Grafana | 10.0 | 容器监控大盘，支持告警 |
| **指标采集** | node_exporter + cAdvisor | latest | 主机指标 + 容器指标 |
| **私有仓库** | Docker Registry | 2.x | 轻量级镜像存储，内网可用 |

## 5. 容器架构

### 5.1 容器编排（docker-compose.yml）

```
项目: blog-platform
├── halo            (博客应用)
│   image: halohub/halo:2.x
│   ports: "8090:8090"
│   volumes: /data/halo:/root/.halo2
│   depends_on: mysql
│
├── mysql           (数据库)
│   image: mysql:8.0
│   ports: "3306:3306"
│   volumes: /data/mysql:/var/lib/mysql
│   environment: MYSQL_ROOT_PASSWORD, MYSQL_DATABASE
│
├── nginx           (反向代理)
│   image: nginx:1.24
│   ports: "80:80", "443:443"
│   volumes:
│     - /opt/blog-platform/nginx.conf:/etc/nginx/nginx.conf:ro
│     - /data/nginx/ssl:/etc/nginx/ssl:ro
│   depends_on: halo
│
├── prometheus      (监控采集)
│   image: prom/prometheus:v2.47
│   ports: "9090:9090"
│   volumes: ./prometheus.yml:/etc/prometheus/prometheus.yml
│
├── grafana         (监控可视化)
│   image: grafana/grafana:10.0
│   ports: "3000:3000"
│   depends_on: prometheus
│
├── node_exporter   (主机指标)
│   image: prom/node-exporter:latest
│   network_mode: host       # 使用宿主机网络，直接暴露端口 9100
│
└── cadvisor        (容器指标)
    image: gcr.io/cadvisor/cadvisor:latest
    ports: "8080:8080"
    volumes:
      - /:/rootfs:ro
      - /var/run:/var/run:ro
      - /sys:/sys:ro
      - /var/lib/docker:/var/lib/docker:ro
```

### 5.2 容器间通信

```
用户请求  ──► nginx:443  ──► halo:8090      (反向代理)
halo      ──► mysql:3306                    (数据库连接)
Prometheus ──► node_exporter:9100           (主机指标采集)
Prometheus ──► cadvisor:8080                (容器指标采集)
Prometheus ──► halo:8090                    (应用指标采集)
Grafana   ──► Prometheus:9090               (监控数据查询)
```

## 7. 后端功能设计

### 7.1 核心模块

| 模块 | 功能 | 技术实现 |
|------|------|---------|
| 文章管理 | 创建/编辑/删除/发布文章 | Halo Admin API |
| 审核工作流 | 草稿→提交审核→审核员通过/驳回→发布 | Halo 内置审核机制 |
| 分类标签 | 文章分类、标签管理 | Halo 分类标签系统 |
| 评论管理 | 评论审核/回复/删除 | Halo 评论系统 |
| 媒体管理 | 图片/附件上传、管理 | 持久化至 /data/halo/attachments |
| 用户管理 | 管理员/编辑/审核员角色权限 | Halo RBAC |
| 系统设置 | 站点标题/SEO/主题配置 | Halo 系统设置 |

### 7.2 审核工作流

```
作者发布文章（状态: 草稿）
       │
       ▼
提交审核（状态: 待审核）
       │
       ├──► 审核员通过 ──► 前台可见（状态: 已发布）
       │
       └──► 审核员驳回 ──► 退回作者修改（状态: 草稿）
```

## 9. 安全设计

| 安全措施 | 实现方式 | 对应需求 |
|----------|---------|---------|
| HTTPS 加密传输 | Nginx SSL 终端，80→443 强制跳转 | SRS-SEC-01 |
| 数据库访问控制 | MySQL 仅绑定业务网 IP，安全组拦截管理网访问 | SRS-SEC-02 |
| 操作审计 | SSH 登录日志（/var/log/secure）+ 命令审计（/var/log/audit） | SRS-SEC-03 |
| 博客审核机制 | 文章默认草稿，需审核员通过才发布 | SRS-APP-02 |
| 最小权限 | 各容器以非 root 用户运行 | — |
| 日志轮转 | Docker 日志限制 size=10m, max-file=3 | — |

## 10. 设计决策记录

| 决策点 | 选择 | 理由 | 备选方案 |
|--------|------|------|---------|
| 博客系统 | Halo v2.x | 国产开源、ARM64 支持、Markdown 原生支持 | WordPress（需更多插件） |
| 数据库 | MySQL 8.0 | 国产化生态完善，ARM64 官方镜像 | PostgreSQL 14 |
| 反向代理 | Nginx | 高性能、成熟、配置灵活 | Traefik（学习成本高） |
| 监控方案 | Prometheus + Grafana | 业界标准、容器原生支持 | Zabbix（重量级） |
| 私有仓库 | Registry | 轻量、够用 | Harbor（功能多但资源消耗大） |
| SSL 证书 | 自签名 | POC 阶段简便，生产可换 Let's Encrypt | 购买商业证书 |
