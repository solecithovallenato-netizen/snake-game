## 2. 一键部署

### 2.1 deploy.sh 脚本说明

脚本位置：`/opt/blog-platform/deploy.sh`

**功能**：在全新 openEuler 22.03 ARM VM 上，30 分钟内完成全量部署。

**执行**：
```bash
cd /opt/blog-platform
chmod +x deploy.sh
./deploy.sh
```

**执行流程**：
1. 检查 Docker 环境（未安装则自动安装）
2. 拉取所有镜像
3. 生成 SSL 自签名证书
4. 创建数据目录（/data/mysql, /data/halo, /data/backup）
5. 启动所有容器（docker compose up -d）
6. 等待 MySQL 就绪（最多等待 60 秒）
7. 初始化 Halo 数据库
8. 输出访问信息

### 2.2 部署后验证

```bash
# 检查容器状态
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

# 测试博客访问
curl -k -o /dev/null -s -w "%{http_code}\n" https://localhost
# 期望: 200

# 测试 Grafana
curl -k -o /dev/null -s -w "%{http_code}\n" https://localhost:3000
# 期望: 200
```

## 3. 容器管理

### 3.1 查看容器状态

```bash
# 查看所有容器
docker ps -a

# 查看容器实时资源占用
docker stats --no-stream

# 查看特定容器日志
docker logs --tail 50 nginx
docker logs --tail 50 halo
docker logs --tail 50 mysql

# 实时跟踪日志
docker logs -f halo
```

### 3.2 启动/停止/重启

```bash
# 启动所有服务
cd /opt/blog-platform
docker compose up -d

# 停止所有服务
docker compose down

# 重启特定容器
docker restart halo
docker restart nginx
docker restart mysql

# 重启所有服务
docker compose restart
```

### 3.3 进入容器调试

```bash
# 进入 MySQL 容器
docker exec -it mysql mysql -u halo_user -p
# 输入密码后进入 MySQL 命令行

# 进入 Halo 容器
docker exec -it halo bash

# 查看 Nginx 配置
docker exec nginx nginx -T
```

## 4. 数据库运维

### 4.1 数据库信息

| 属性 | 值 |
|------|-----|
| 容器名 | mysql |
| 版本 | MySQL 8.0.x |
| 端口 | 3306（仅业务网） |
| 数据库名 | halo |
| 用户名 | halo_user |
| 数据路径 | /data/mysql（宿主机）→ /var/lib/mysql（容器） |
| 字符集 | utf8mb4 |

### 4.2 手动备份

```bash
# 在宿主机执行
docker exec mysql mysqldump -u root -p"${MYSQL_ROOT_PASSWORD}" \
  --single-transaction \
  --routines \
  --triggers \
  halo | gzip > /data/backup/manual_backup_$(date +%Y%m%d_%H%M%S).sql.gz

# 查看备份文件
ls -lh /data/backup/
```

### 4.3 自动备份（backup.sh + crontab）

**backup.sh 脚本**位于 `/opt/blog-platform/backup.sh`：

```bash
cd /opt/blog-platform
chmod +x backup.sh

# 手动执行备份
./backup.sh

# 设置定时任务（每日凌晨 2:00）
crontab -e
# 添加: 0 2 * * * /opt/blog-platform/backup.sh

# 查看定时任务
crontab -l
```

**backup.sh 功能**：
1. 执行 mysqldump 全量备份
2. 压缩为 .sql.gz 格式
3. 命名格式：`backup_YYYYMMDD_HHMMSS.sql.gz`
4. 自动清理 7 天前的备份文件
5. 输出备份日志（记录文件大小和耗时）

### 4.4 从备份恢复

```bash
# 场景: 数据库故障，需要从最新备份恢复

# 1. 找到最新备份文件
ls -t /data/backup/backup_*.sql.gz | head -1

# 2. 解压备份文件
gunzip -c /data/backup/backup_20260701_020001.sql.gz > /tmp/restore.sql

# 3. 恢复数据库
docker exec -i mysql mysql -u root -p"${MYSQL_ROOT_PASSWORD}" halo < /tmp/restore.sql

# 4. 重启 Halo 应用
docker restart halo

# 5. 验证恢复
curl -k -o /dev/null -s -w "%{http_code}\n" https://localhost
# 期望: 200
```

### 4.5 验证数据持久化

```bash
# 模拟容器删除场景
docker rm -f mysql

# 重新启动 MySQL 容器
cd /opt/blog-platform
docker compose up -d mysql

# 验证数据仍在
# 登录博客后台，检查文章是否完整
```

## 5. 日志管理

### 5.1 日志位置

| 日志类型 | 位置 | 说明 |
|----------|------|------|
| 容器日志 | `docker logs <容器名>` | 标准输出/错误输出 |
| Docker 日志 | `journalctl -u docker` | Docker 守护进程日志 |
| SSH 登录日志 | `/var/log/secure` | 所有 SSH 登录记录 |
| 命令审计日志 | `/var/log/audit/audit.log` | 用户操作命令记录 |
| 备份日志 | `/data/backup/backup.log` | 备份执行记录 |
| Nginx 访问日志 | `docker logs nginx` | HTTP 请求记录 |

### 5.2 查看日志

```bash
# 查看最近 100 行容器日志
docker logs --tail 100 halo

# 搜索错误日志
docker logs halo 2>&1 | grep -i error

# 查看谁登录过系统
last

# 查看审计日志（最近 50 条命令）
ausearch -m USER_CMD | tail -50

# 查看 SSH 登录失败记录
grep "Failed password" /var/log/secure | tail -20

# 查看备份执行日志
cat /data/backup/backup.log
```

### 5.3 日志轮转

Docker 容器日志自动轮转（已在 daemon.json 配置）：
- 单文件最大 10MB
- 最多保留 3 个文件

```bash
# 查看 docker 日志配置
cat /etc/docker/daemon.json
# {
#   "log-driver": "json-file",
#   "log-opts": {
#     "max-size": "10m",
#     "max-file": "3"
#   }
# }
```

## 6. 监控运维

### 6.1 监控架构

```
Prometheus (采集) ──► Grafana (展示)
    │
    ├── node_exporter  ← 主机指标 (CPU/内存/磁盘/网络)
    ├── cadvisor       ← 容器指标 (CPU/内存/网络/IO)
    └── halo           ← 应用指标 (请求数/响应时间)
```

### 6.2 访问监控

| 组件 | 地址 | 默认账号 |
|------|------|---------|
| Grafana | `https://<业务IP>:3000` | admin/admin（首次登录需修改） |
| Prometheus | `http://<业务IP>:9090` | 无认证（仅内网） |

### 6.3 监控大盘查看

1. 浏览器打开 `https://192.168.20.10:3000`
2. 登录 Grafana
3. 进入「Dashboards」→「容器监控大盘」
4. 查看以下指标：

| 指标面板 | 内容 |
|----------|------|
| 主机概览 | CPU 使用率、内存使用率、磁盘使用率、网络流量 |
| 容器概览 | 7 个容器运行状态、CPU/内存/网络 IO 排名 |
| Halo 概览 | 博客请求数、响应时间、错误率 |
| MySQL 概览 | 连接数、查询速率、慢查询、缓冲池命中率 |

### 6.4 检查监控 Target 状态

```bash
# SSH 到 VM-02
# 查看 Prometheus Targets
curl -s http://localhost:9090/api/v1/targets | python3 -m json.tool | grep -E '"job"|"health"'

# 期望所有 target 的 health 为 "up"
```

## 8. 故障处理

### 8.1 容器异常退出

```bash
# 查看退出容器
docker ps -a --filter "status=exited"

# 查看退出原因
docker logs --tail 50 <容器名>

# 尝试重启
docker restart <容器名>

# 如果无法重启，查看详细日志
docker inspect <容器名>
```

### 8.2 磁盘空间不足

```bash
# 检查磁盘使用
df -h

# 清理 Docker 未使用的资源
docker system prune -a --volumes

# 清理旧备份文件
ls -lt /data/backup/ | tail
rm /data/backup/backup_20260601_*.sql.gz  # 删除过旧备份

# 检查大文件
du -sh /data/* | sort -rh
```

### 8.3 MySQL 无法连接

```bash
# 检查 MySQL 容器是否运行
docker ps | grep mysql

# 如果未运行，启动它
docker compose up -d mysql

# 检查端口绑定
docker exec mysql netstat -tlnp | grep 3306

# 检查安全组
# 确认 FC 安全组允许业务网（192.168.20.0/24）访问 3306
```

### 8.4 HTTPS 证书过期

POC 阶段使用自签名证书（有效期 365 天），到期后续期：

```bash
# 重新生成自签名证书
cd /opt/blog-platform
openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
  -keyout ssl/blog.key -out ssl/blog.crt \
  -subj "/CN=192.168.20.10"

# 重启 Nginx
docker restart nginx
```

### 8.5 完整系统瘫痪恢复

```bash
# 最坏情况：VM 不可用
# 1. 在 FusionCompute 中恢复最新快照
# 2. 如果快照不可用，从头部署：
cd /opt/blog-platform
./deploy.sh

# 3. 从备份恢复数据库
# 参考 4.4 节
```

## 10. 常用命令速查

```bash

docker compose up -d              # 启动所有服务
docker compose down               # 停止并移除所有容器
docker compose restart            # 重启所有服务
docker restart <容器名>             # 重启单个容器

# ========== 状态查看 ==========
docker ps                         # 运行中的容器
docker ps -a                      # 所有容器
docker stats --no-stream          # 容器资源使用
docker logs --tail 100 <容器名>    # 容器日志

# ========== 数据库 ==========
docker exec -it mysql mysql -u root -p  # 进入 MySQL
./backup.sh                       # 手动备份

# ========== 部署 ==========
./deploy.sh                       # 一键部署

# ========== 系统 ==========
df -h                             # 磁盘空间
free -h                           # 内存使用
uname -m                          # 架构（应为aarch64）
```
